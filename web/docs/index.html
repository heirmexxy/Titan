Titan API v1

The Titan API gives your systems the readings, alerts and storage-condition history from sites you own or that have been shared with you. Every reading Titan stores was signed by the device that took it.

Base URL: https://titan.kitovu.com.ng/v1. All responses are JSON. Times are ISO 8601 in UTC.

Authentication

Send your API key as a bearer token on every request. Keys are issued by Kitovu from the Titan admin panel and are shown once.

curl https://titan.kitovu.com.ng/v1/sites \
  -H "Authorization: Bearer tk_live_…"

Each key carries scopes:

ScopeAllows
read:readingsLatest readings, history, condition reports and proofs
read:alertsListing alerts
manage:webhooksCreating and deleting webhook subscriptions
manage:grantsSharing your own sites with other organisations

StorageX integration

StorageX uses Titan to show the condition of the stock behind each warehouse receipt.

1. Link the IDs once

When a warehouse is set up in Titan, its StorageX warehouse ID is saved as the site's external ID, and each StorageX lot ID is saved on the matching stack. Device channels name the zone and stack, for example z1/stack-a/mst1.

2. Find the Titan site for a warehouse

GET /v1/sites?ref=SX-WH-001

3. Subscribe to alerts

POST /v1/webhooks
{ "url": "https://storagex.kitovu.com.ng/hooks/titan", "events": ["alert.*", "device.offline"] }

When an alert opens on a stack, flag the lots and receipts stored there. Store the returned secret to verify each delivery.

4. Attach a condition report to a receipt

GET /v1/sites/{siteId}/conditions?lot=LOT-2026-114&from=2026-10-01T00:00:00Z&to=2026-11-13T00:00:00Z

Use the receipt's storage period as from and to. Show lenders the min, max and average for each reading, the alerts during the period, data completeness, and whether moisture went above the crop's safe level.

5. Show live conditions

GET /v1/latest?site={siteId}

Third-party warehouses and lenders

For a warehouse owned by another organisation, the owner grants StorageX access (see grants). The same calls then work for that site. A lender such as a microfinance bank can be given its own key and a grant covering only the warehouses it finances.

Storage conditions

GET/v1/sites/{id}/conditionsread:readings

A summary of conditions over a period, for the whole site, a zone or one stack.

ParameterMeaning
from, toPeriod, default the last 30 days. Up to 366 days.
lotStorageX lot ID (external ID of a stack)
stackOr the zone and stack code directly, e.g. z1/stack-a. Use just z1 for a zone.

For a stack, the report includes that stack's produce readings plus the zone's air readings. Periods up to 92 days are summarised by hour, longer ones by day; completeness is the share of those hours or days that have data.

Reading history

GET/v1/readingsread:readings
ParameterMeaning
site or deviceLimit to one site or device. Without either, all visible sites.
metricOne or more metric keys, comma separated, e.g. air.temperature,produce.moisture
channelOne channel, e.g. z1/stack-a/mst1
from, toDefault: the last 24 hours. Up to 366 days.
intervalraw (default), 1m, 1h or 1d. Aggregates return avg, min, max and count.
limitUp to 50,000 rows, default 10,000

Raw readings carry labels you should respect:

FieldMeaning
qualityok, suspect or fault as reported by the device. Out-of-range values are never returned.
bufferedTaken during a connection outage and sent later, with the original time
timeEstimatedThe device clock was not set; Titan estimated the time
derivedCalculated by Titan (dew point, equilibrium moisture, VPD)
integritydevice-signed (Ed25519), shared-secret (approved third-party devices), or derived
seqThe device message number; use it to fetch a proof

Reading proofs

GET/v1/readings/proof?device={id}&seq={seq}read:readings

Returns the original signed message, the device's public key and Titan's own check. Anyone can verify it independently:

import { createPublicKey, verify } from 'node:crypto';
const raw = Buffer.from(proof.publicKey, 'base64url');                      // 32-byte Ed25519 key
const key = createPublicKey({ key: Buffer.concat([Buffer.from('302a300506032b6570032100', 'hex'), raw]), format: 'der', type: 'spki' });
const ok = verify(null, Buffer.from(proof.payload, 'base64url'), key, Buffer.from(proof.signature, 'base64url'));

Alerts

GET/v1/alerts?site={id}&status=openread:alerts

status is open, acknowledged or resolved. Codes include threshold, device_offline, tamper, intruder_detected, door_opened, sensor_error and power_lost.

Metric registry

Every metric key with its unit, label and valid range, e.g. air.temperature (°C), produce.moisture (% wet basis), water.do (mg/L).

Deliveries

Titan POSTs { "event", "created_at", "data" } with headers X-Titan-Event and X-Titan-Signature: t=<unix>,v1=<hex>. Reply with any 2xx within 10 seconds. Failed deliveries are retried 5 more times over about 30 minutes.

import { createHmac, timingSafeEqual } from 'node:crypto';
function verifyTitan(rawBody, header, secret) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;          // reject old deliveries
  const expected = createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  return timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}

Sharing data (grants)

The owner of a site decides who else can see it. A grant names the organisation, the sites, the readings and the period. Grants can be revoked at any time and every read is logged.

POST/v1/grantsmanage:grants
{ "granteeOrgId": "…", "siteIds": ["…"], "metrics": ["produce.moisture", "air.humidity", "air.temperature"],
  "validFrom": "2026-11-01T00:00:00Z", "validTo": "2027-05-01T00:00:00Z", "live": true }

Leave siteIds or metrics out to share all. live lets the grantee receive webhooks for those sites.

GET/v1/grants

Grants you have given and received.

DELETE/v1/grants/{id}

Errors and limits

Errors return { "error": "code", "message": "…" } with the matching HTTP status: 400 bad request, 401 missing or invalid key, 403 missing scope, 404 not found or not visible to you, 429 rate limited.

Each key may make 600 requests per minute. For live data, use webhooks rather than polling.
